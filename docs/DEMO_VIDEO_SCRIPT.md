# Demonstration recording script

Target length: about 6–7 minutes. Use the local demo and synthetic files. Record the actual screen and outcome.

| Time | Screen action | Explanation |
|---|---|---|
| 0:00–0:40 | Show login and introduce the team | Explain the problem of tracking versions and reviewer feedback. |
| 0:40–1:40 | Researcher saves a draft and submits research-v1.txt | Show metadata, generated version, hash and submission time. |
| 1:40–2:30 | Compare original and altered files | Show MATCH and MISMATCH. Explain that hashing checks bytes, not patentability. |
| 2:30–3:15 | Admin assigns two reviewers | Explain distinct active reviewers and no self-review. |
| 3:15–4:15 | Reviewers submit decisions | Show two approvals completing a version; use a separate version to illustrate rejection if time permits. |
| 4:15–5:05 | Submit a second version and open history | Explain preserved older snapshots and version-specific access. |
| 5:05–5:45 | Show receipt and audit page | Explain internal records and the unsigned receipt. |
| 5:45–6:30 | Show architecture or final slide | Summarise Java, Servlet/JSP, JDBC, database and module ownership. |

Check audio, cursor visibility and text size before recording. Do not include real credentials, personal research or claims about tests that were not run.
